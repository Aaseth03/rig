# context-doctor

Keeps a repo's `.context/` system-map (built by the vendored `icm-architect`
skill) both current and readably sized once the repo is under active
development. This skill never edits anything under `skills/icm-architect/` —
that folder is vendored and third-party. All behavior here lives in this
skill and in two rig-owned hooks (`hooks/context-size/context-size-check.py`,
`hooks/context-stale/staleness-check.py`).

Every map this skill sets up is rooted at `.context/` at the project root —
never `map/`. This is a deliberate standardization, not a default that can
be reconsidered per repo.

## Which branch to run

- If `.context/` does not exist yet at the project root, run **Branch A**
  regardless of what args (if any) this skill was invoked with.
- If invoked with args containing `init` and `.context/` already exists,
  still run Branch A — it re-runs the audit as a restructure pass.
- Otherwise (bare `/context-doctor`, `.context/` already exists), run
  **Branch B**.

---

## Branch A — init

This branch pre-decides exactly two things that `icm-architect` would
otherwise ask about interactively: which form to build (System map) and
where to root it (`.context/`, never `map/`). It does **not** skip or
shortcut anything else `icm-architect` does — every inventory/catalog/
nouns/verbs/effects stop-and-check that skill asks for during its own audit
pipeline still fires, and this skill's agent must honor each one before
continuing to the next slice.

1. Invoke the `Skill` tool a second time, with:
   - `skill`: `"icm-architect"`
   - `args`: `"Restructure mode, System map form. Root the map at .context/ at the project root — do not propose or use map/. Run the normal audit pipeline (inventory, catalog, nouns, verbs, effects) with its usual human-gated stops. Make the repo wide AGENTS.md file at project root and not in the map root. Do not use CLAUDE.md, only AGENTS.md"`

   Wait for that skill's audit pipeline to complete, including all of its
   own human gates. Do not proceed to step 2 until `icm-architect` reports
   the pipeline finished.

2. Once `.context/objects/_index.md` and `.context/effects/CONTEXT.md` both
   exist, read both in full.

3. Generate `.context/effects/UPKEEP.md` — a new file, deliberately
   *separate* from `effects/CONTEXT.md` (a future `icm-architect` re-audit
   may regenerate that file and would otherwise silently wipe this table).
   `UPKEEP.md` is the write-back mirror of `effects/CONTEXT.md`: same
   source-pattern-to-card mappings, opposite timing — `effects/CONTEXT.md`
   says what to open *before* changing something; `UPKEEP.md` says what to
   re-verify *after* you changed it.

   Derive the rows like this, rather than copying any fixed template:

   - Walk `objects/_index.md`'s noun table. Keep only rows whose `Universe`
     column is `live` and whose `Card` column links to a real card (skip
     `ghost` stubs with no card, and `leftover` nouns explicitly marked as
     having no card — there is nothing meaningful to re-verify for either).
   - For each surviving live noun, find its corresponding row in
     `effects/CONTEXT.md` (matched by which card it points at) and carry
     over that row's *source pattern* (the "if you're changing X" left-hand
     glob or path) unchanged.
   - Emit one `UPKEEP.md` row per surviving noun: the source pattern in the
     left column, a relative link to the same card in the right column.
   - Do not carry over `effects/CONTEXT.md` rows that point at install
     *output* (e.g. `.claude/`, `.github/`) rather than source — there is
     nothing to write back to for generated output.

   Write the file with this header, followed by the derived table:

   ```markdown
   # effects/UPKEEP.md — write-back index

   Companion to effects/CONTEXT.md, but reversed: if you changed the file
   in the left column, the card in the right column needs re-verifying
   (status/date/citations) against the new source. Generated by
   context-doctor init from objects/_index.md — do not hand-edit; re-run
   context-doctor to regenerate.

   | Source changed | Refresh after |
   |---|---|
   ```

4. Add exactly one new row to the project's root entry file (`AGENTS.md` if
   it exists, else `CLAUDE.md`) in whatever routing table already exists
   there (e.g. a "Common tasks" table) — for example:

   `**What context needs refreshing after I change X?** → .context/effects/UPKEEP.md`

**Human gate:** stop here. Show the generated `UPKEEP.md` in full and the
diff to the entry file. Do not consider init done, and do not move on to
any further action, until a person has read both.

## Branch B — maintenance pass

Only valid once `.context/` already exists (see branch selection above).

1. Read `.context/logs/CONTEXT_SIZE_LOG.md` and
   `.context/logs/CONTEXT_STALE_LOG.md`, if present. If neither exists or
   both are empty, report that there is nothing to remediate and stop.

2. For each entry in `CONTEXT_SIZE_LOG.md` (a card over the line
   threshold), open the file and bring it back under the threshold by
   splitting or compressing. Apply this judgment while doing so:

   - Find the load-bearing claims first — especially any "If you change
     this" Hits/Does not hit waterfall — and make sure they survive the
     edit intact and correct. A card getting shorter must never make a
     waterfall less accurate.
   - Prefer **splitting** when the card is really doing the job of more
     than one noun-cluster (it describes two things an editor would ask
     about separately).
   - Prefer **compressing** when the bloat is restated as-built behavior
     rather than a citation — if the card is narrating what the code does
     instead of pointing at the file that owns it, cut the narration and
     replace it with a citation (`path:line`).
   - Keep every card's required shape intact through the edit: one-line
     identity, the load-bearing why, shape with citations, connected-to,
     Hits/Does not hit, surfaces, and a single `See` link to source.
   - Re-verify surviving claims against current source before leaving a
     card marked `status: verified` — that status requires a date plus a
     branch/commit plus citations. If a claim can't be re-confirmed right
     now, mark the card `stale` rather than leave a confidently wrong date.
   - Don't invent a new empty `processes/` or `effects/` shelf just to
     move lines out of one file — three verified clusters beat seven
     imagined ones.

3. For each entry in `CONTEXT_STALE_LOG.md` (a card flagged by the
   staleness hook), open both the named card and the source path that
   triggered the flag. Re-verify the card's claims against that source.
   If they still hold, bump the card's date and citations. If they don't,
   rewrite the affected section citing the new source, keeping the same
   required sections listed above. Re-verify any Hits/Does not hit
   waterfall touching the changed noun.

4. As each entry is actually fixed, remove it from its log file — mirror
   the same upsert/remove pattern `hooks/context-size/context-size-check.py`
   already uses (rewrite the log with the fixed entry's line omitted,
   keep the rest, preserve the header).

**Human gate:** before writing any fix, present the full list of files
this pass intends to touch and why (which log, which threshold or which
staleness trigger). Do not auto-fix silently in bulk — a person confirms
the list first.
